-------------
Build Process
-------------

- Refer to makefile to see how individual files are built.

- Some files are generated by Perl scripts and are not part of the repository.

- The EBNF compiler (ebnfcomp, GPLv3, same author) is vendored in the
  'ebnfcomp' directory (formerly a git submodule); a plain 'git clone URL' is
  enough. It is built by the makefile ('cd ebnfcomp && make').

- Dependencies in makefile might be incomplete; use 'make -B' to do a full
  rebuild.

- If at any point, a build error occurs, please let me know, so that I can have
  a look at it.

- The font is defined in the file "8x12font1.txt", which is converted to a hex
  dump in file "8x12font1.inc" by the "extract_font.pl" script.
  "8x12font1.inc" is included by "8x12font1.nasm".

- The token list (actually, keyword list) is defined in file "tokenlist.txt".
  It is used by script "extract_tl.pl" to generate "tokendef.inc", which is
  included by "tokens.nasm". It is also read by "build_main_ebnf.pl" to create
  the token-based (binary) EBNF. See chapter "Tokenization Process" to read
  more about the tokenization process.

- The main language syntax comes from the file "defaultsyntax.ebnf". It is read
  by "build_main_ebnf.pl" to create "main.ebnf", which is the main language EBNF
  file, matching against binary tokens as opposed to text. This "main.ebnf" file
  is then run through the EBNF compiler (ebnfcomp) to generate "mainsyntax.inc"
  and "mainsyntax.nasm", which is the parsing table. See chapter "Syntax
  Analysis" to see how it works.

--------------------
Tokenization Process
--------------------

- Input lines are fully converted to tokens before being run through the syntax
  analyzer.

- Cf. file "build_main_ebnf.pl" to see how individual tokens are encoded.

- Anything that is not recognized will be converted to an identifier.
  Identifiers are encoded as FE TYPE LEN ...

- Number tokens are encoded as 01 BASE VALUE.q
  NOTE that VALUE is encoded in big endian (network byte order).

- Operator tokens are hardcoded in the tokenization process.
  They are encoded as 02 ID

- Currently, there is a maximum of 256 keywords.
  They are encoded as 03 ID
  The keyword list is specified 'tokenlist.txt' and used during the build
  process. Order affects the ID assigned to each keyword, thus as soon as
  there are users of AsmBASIC, new ones should only ever be appended, never
  inserted at arbitrary positions into the file.

- String literals are encoded as FF LEN.w ...
  NOTE that LEN is encoded in big endian (network byte order).

-----------------------
Syntax Analysis Process
-----------------------

- Syntax analysis (in "syntree.nasm") uses the in-memory parsing tree created
  in "parsetree.nasm".

- Syntax tree nodes are presently just pointers to the matching parse tree nodes
  (and token bytes, if any), and a list of subnodes.

- Some optimizations are applied to reduce the overall number of result nodes in
  the tree. The goal here is so complexity becomes minimal for later code
  generation.

- A "cooked syntax tree" (csn tree) is created from the "raw syntax tree" (stn
  tree) that makes objects from the syntax tree more directly accessible, and
  also employs some further optimizations. Beginnings (i.e., root nodes) of
  statements and expressions are clearly marked. This makes code generation
  much easier.

------------------
Three-Address Code
------------------

   +--------+--------+--------+--------+
   | Opcode | Target | Sourc1 | Sourc2 |
   +--------+--------+--------+--------+

- How to encode Targets/Sources?
  o Pointer to descriptor.

- How to encode S/T descriptor?
  o Needs to differentiate between temporary variables and user-defined
    variables and function/procedure arguments.
  o Descriptors must be context sensitive, i.e. have parent descriptors,
    to support state changes.
  o States of user-defined variables:
    - Global or local to current procedure/function.
    - Automatic declaration (unDIMensioned arrays are single-dimensional and
      from 0..10).
    - Numbers are preallocated with 0, Strings with "".
    - Initialized by programmer using assignment statement.
    - (Arrays) Dimensioned by programmer using DIM statement.
    - Erased by programmer using ERASE statement.

- Opcodes (can be either abstract or concrete, depending on code generation
    stage)
  o BEGINCALL t
    - argument context
    - t: context
  o ARGUMENT t,s1
    - assigns a temporary variable (used as a parameter) to an argument context
    - t: context, s1: var
  o RESULT t,s1
    - assigns a temporary variable (used as a result) to an argument context
    - t: context, s1: var
  o CALL t,s1
    - issues a call to a function or procedure
    - t: context, s1: func/proc reference
  o ENDCALL t
    - argument context
    - t: context
  o AND, OR, XOR, NOT, ADD, SUB, MUL, DIV, CONCAT, NUMEQ, NUMNE, NUMGT, NUMLT,
    NUMGE, NUMLE, STREQ, STRNE, STRGT, STRLT, STRGE, STRLE, ...
    OP t,s1[,s2]
    - built-in operators
    - t: var, s1,s2: var/value
  o BRIT, BRIF; BRANCH
    OP t[,s1]
    - branch if TRUE / FALSE; unconditionally
    - t: target location
    - s1: var
  o MOVE t,s1
    - assignments
    - t: var, s1: var/value
  o GLOBAL t
    - declare global variable
    - t: var
  o DIMENSION t,s1
    - dimension an array (always one-dimensional, regardless of user dimensions)
    - t: target variable
    - s1: descriptor holding following fields:
      - user-defined dimensions
      - actual dimension
      - DYNAMIC/ASSOC mode indicator
  o ERASE t
    - ERASEs an array
    - t: target variable
  o BEGINFRAME t
    - begins a (stack) frame context
    - t: context
  o LOCAL t,s1
    - declares a frame local variable
    - t: context, s1: var
  o REFLOCAL t,s1
    - references a global variable in a frame (as a local variable)
    - t: context, s1: var
  o REFGLOBAL t,s1
    - references a global variable in a frame (as a global variable)
    - t: context, s1: var
  o ENDFRAME t
    - ends a (stack) frame context
    - t: context
  o BEGINLOOP t
    - creates loop context
    - t: context
  o ITERATE t
    - iterate a loop
    - t: context
  o AGAIN t
    - repeats loop body without iteration
    - t: context
  o LEAVE t
    OP t
    - leave a loop
    - t: context
  o ENDLOOP t
    - deletes loop context
    - t: context
  o BEGINCOND t
    - begins a conditional context
    - t: context
  o CONDEXPR t,s1
    - sets the conditional expression
    - t: context, s1: expr location
  o CONDTRUE t,s1
    - sets the conditional expression's TRUE branch
    - t: context, s1: code location
  o CONDFALSE t,s1
    - sets the conditional expression's FALSE branch
    - t: context, s1: code location
  o ENDCOND t
    - ends a conditional context
    - t: context
  o LABEL t
    - defines a label at the "current code location"
    - t: var
