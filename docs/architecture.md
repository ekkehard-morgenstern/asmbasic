# Architecture

## Pipeline

```
 keyboard / stdin
       │  pb_readln  (patch bay → sdl_readln | std_readln)
       ▼
 text line (UTF-8, ≤ 8191 bytes)                       main.nasm: getline / main_loop
       │  tokenize                                     tokens.nasm, toknum.nasm, unicode.nasm
       ▼
 token string in `tokenpad` (binary tokens)
       │  crtsyntree                                   syntree.nasm
       │     walks the in-memory parse tree            parsetree.nasm  ← mainsyntax.nasm (generated by ebnfcomp)
       ▼
 raw syntax tree (stn_*)       ── optional dump: --stnprint   (prtsyntree)
       │  cooksyntree                                  cookedsyntree.nasm
       ▼
 cooked syntax tree (csn_*)    ── dump: --csnprint (currently always on)
       │
       ▼
 [code generation — not implemented; `; tbd` in main_loop]
```

On a syntax error `main_loop` prints `? Syntax error` (nothing matched) or `? Syntax error near <<…>>`
(a prefix matched but tokens remain: `*stn_tokenptr != 0`) and prompts again. After each line both trees are freed
(`delcookedsyntree`, `delsyntree`).

## Start-up sequence (`main`)

1. `init_locale` — set the C locale from `LANG`/environment (needed for `mbrtowc`).
2. `getargs` — parse command line (`--help`, `--sdl`, `--stdio`, `--curses` (not implemented), `--testtok`,
   `--dumppt`, `--stndebug`, `--stnprint`, `--csnprint`; short forms `-h -d -s -c`). A filename argument is stored in
   `filename` but not used yet.
3. `chkcputype` — CPUID check (see `support-modules.md`).
4. `initparsetree` — convert the packed, generated grammar table into the pointer-based in-memory parse tree.
5. `--dumppt` → dump the parse tree and exit.
6. Select console: `pb_initstdio` (`--stdio`/`--curses`) or `pb_initsdl` (default; launches the SDL worker thread).
7. `init_tokenizer` — build the token hash tables from the built-in token init blocks.
8. `--testtok` → `tokenizer_test` (tokenize + detokenize loop), else `main_loop`.

## Modules

| Layer | Module(s) | Responsibility |
|---|---|---|
| Driver | `main.nasm` | options, REPL loop, error messages |
| Lexical | `tokens.nasm`, `toknum.nasm`, `tokendef.inc`, `keywords.inc`, `tokenlist.txt` | text ⇄ binary tokens |
| Grammar | `defaultsyntax.ebnf`, `main.ebnf`, `mainsyntax.nasm/.inc` | language definition and generated parse table |
| Parsing | `parsetree.nasm`, `syntree.nasm`, `stnflgtbl.nasm`, `parsenodename.nasm` | parse table → tree; match tokens; raw syntax tree |
| Semantic prep | `cookedsyntree.nasm`, `csntext.inc` | flatten raw tree into typed nodes (statement/expression/line…) |
| Console | `patchbay.nasm`, `stdconsole.nasm`, `sdlcon*.nasm`, `8x12font1.nasm` | pluggable terminal |
| Base | `xalloc`, `unicode`, `locale`, `cpuinfo`, `osversion` | allocation, UTF-8, environment checks |
| Draft | `threeaddrcode.inc`, `collect.nasm` | unused design sketches |

All modules are separately assembled `elf64` objects linked by `gcc` with `-lrt -lSDL2 -pthread -no-pie`; they call the
C library (`malloc`, `fprintf`, `snprintf`, `mbrtowc`, `strcmp`…) directly.

## Design decisions (from `implnotes.txt` and the code)

- **Grammar-driven parser, not hand-written.** The language syntax is an EBNF file. `build_main_ebnf.pl` rewrites it to
  match *binary tokens*; `ebnfcomp` turns it into a ROM-style table in assembly; at start-up that table is expanded to a
  pointer tree for fast traversal.
- **Whole line is tokenized before parsing.** Unknown words become identifiers, so the tokenizer cannot fail on
  content (only on buffer exhaustion).
- **Keywords are binary tokens `03 id`.** At most 256; ID = line order in `tokenlist.txt`.
- **Syntax tree minimisation.** The raw tree removes trailing null branches and collapses single-child productions; the
  cooked tree then removes pure container nodes and marks statement/expression/line roots, to make code generation
  simple.
- **Console abstraction** through four function pointers so the same driver runs on stdio or SDL.
- **SDL console is a client/server pair**: a worker thread owns the window and renders the text screen; the client side
  (main thread) prints into shared buffers and reads input from a keyboard ring buffer; they synchronise through an
  `epoll` + `eventfd` mechanism.
- **Deliberate `enter`/`leave` frames** for clarity (see `conventions.md`).

## Memory ownership

| Object | Allocated by | Freed by | Lifetime |
|---|---|---|---|
| In-memory parse tree | `initparsetree` (`xalloc`) | never | program |
| Token maps / hash tables | `init_tokenizer` | never | program |
| `linebuf`, `tokenpad` | static `.bss` | — | program (reused per line) |
| Raw syntax tree | `crtsyntree` | `delsyntree` (`free_stn`) | one input line |
| Cooked syntax tree | `cooksyntree` (`crt_csn`) | `delcookedsyntree` (`del_csn`) | one input line |

The cooked tree points into token bytes in `tokenpad` (its `csn_data`), so the token buffer must not be overwritten
while the cooked tree is alive. (Inferred from `csn_data` being a data pointer; verify before relying on it.)

## Threads

Only the SDL console uses threads: the main thread runs the REPL; `sdl_worker` (created with `SDL_CreateThread`) runs
the window, event pump and renderer. Shared state is in `sdlconshr.nasm` (flags like `sdl_worker_doquit`,
`sdl_want_input`, the screen buffers and the cursor position); the keyboard ring buffer is protected by a pthread
mutex. See `console-subsystem.md`.
